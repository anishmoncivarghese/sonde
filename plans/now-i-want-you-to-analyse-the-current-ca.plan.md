- [ ] FOCUS-3: Build probe-local evidence ordering and seed resolution

- [ ] FOCUS-4: Generate throwaway static-flow Markdown packets

## Phase 3 — productize only projections authorized by FOCUS-7

- [ ] EXPLAIN-1: Add strict explanation request parsing and symbol resolution
  Proceed only if `probes/focused-explanation/VERDICT.md` records at least one projection `PASS`. Add internal request/bounds/error types and a reusable resolver under `src/explain/` that accepts stable key, unique qualified name, then unique short name; missing names must include the attempted identifier and a `sonde search` suggestion, while ambiguity must return bounded candidate stable keys and never score-select one. Validate defaults of depth 3/nodes 100/time 2 seconds, reject non-positive values and values above depth 6/nodes 500, require exactly symbols or `--from-git-diff` for impact, and keep `--question` as metadata only. Add failing-first unit tests for every resolution and validation branch. Do not introduce a public schema, JSON mode, HTML, or a fourth MCP tool. Change nothing else.

- [ ] EXPLAIN-2: Add explanation-specific indexed-evidence readers and the shared comparator
  Add narrow `Store`/`src/explain/` read APIs that return symbol locations/ranges, edge ids, tiers, confidence, site lines, fan-in/exported inputs, external/unresolved rows, indexed-at provenance, and compiler/pyright provenance without exposing raw SQL to renderers. Implement the one total comparator from spec §4 and duplicate-edge representative/site aggregation once for every projection. Tests must prove `COMPILER > LEXICAL > HEURISTIC`, score uses the candidate's displayed depth with `pathFocusMatch: false`, confidence is consulted only for HEURISTIC ties, missing lines sort last, edge id is the final tie-breaker, and all sites survive collapse. Do not alter existing `query_graph` or impact ordering yet. Change nothing else.

- [ ] EXPLAIN-3: Assemble truthful evidence state and shared node allowances
  Add an internal explanation context builder that calls `ensureFresh`, reports root hash, revision, nullable dirty state, stable index time, freshness/drift, parse failures, compiler/pyright provenance, warnings, and remaining depth/node/time/token allowances. Preserve partial results for drift, parse, missing toolchain, and truncation, but turn no index and schema mismatch into typed non-zero errors with exact rebuild commands; include no volatile generation timestamp in stdout semantics. Unit-test fresh, inline-refreshed, dirty, over-drift, parse-failure, missing-toolchain, no-index, and schema-mismatch states without executing repository code. Change nothing else.

- [ ] FLOW-1: Implement deterministic resolved forest traversal
  Proceed only if flow is authorized. Add `src/explain/flow.ts` forest mode over outgoing resolved CALLS plus non-duplicate REFERENCES. Run level-order BFS with the seed pre-discovered, sort the whole frontier with the shared comparator, retain one parent per destination, then emit one complete root-to-node path per accepted tree edge depth-first with comparator-ordered siblings and numbered first appearances; record self/ancestor edges as cycles and other rediscovery as shared nodes without enqueueing either. Enforce request depth/node/time bounds while building and expose exact bound/omission state. Add tests for sibling ordering, self-loop, ancestor cycle, diamond sharing, duplicate call/reference sites, exact-fit bounds, and deterministic prefixes. Change nothing else.

- [ ] FLOW-2: Implement every bounded equal-shortest targeted path
  Proceed only if flow is authorized. Add `--to` traversal with a distance map and comparator-ordered predecessor lists: finish the entire predecessor frontier when the target first appears, retain every equal-distance predecessor, discard longer arrivals, and reconstruct simple paths depth-first through the increasing-distance DAG. Mark repeated symbols `shared with path N`, never cycle; return success with the exact no-indexed-path wording when unreachable; under bounds emit the deterministic fitting prefix and known omitted-path count. Test alternate equal parents, cycles and longer detours, target-at-seed, unreachable targets with unresolved evidence, node/time truncation, and stable path numbering. Change nothing else.

- [ ] FLOW-3: Add possible links, implementation fan-out, and scoped caveats
  Proceed only if flow is authorized. For the seed and resolved primary-path nodes only, add one non-recursive outgoing HEURISTIC CALLS/REFERENCES lookup and at most one reverse IMPLEMENTS/INHERITS hop, ordered by the shared comparator and scored at owner depth plus one; never add these rows to BFS parents/predecessors or bridge a missing segment. Aggregate scoped external/unresolved counts and named reasons, consume only the remaining semantic-node allowance, and label every inferred implementer “implementation fan-out.” Tests must prove auxiliary rows cannot extend paths, heuristic calls remain possible links, fan-out direction is correct, and caps disclose rather than silently drop evidence. Change nothing else.

- [ ] IMPACT-1: Map working-tree diff hunks to current symbols with hard Git errors
  Proceed only if impact is authorized. Extend `src/repo/git.ts` through `RepoBoundary`-safe inputs to parse the current tracked working-tree diff's zero-context changed ranges, then select indexed symbols whose current ranges overlap those hunks; list added/modified files or hunks that map to no symbol as omissions rather than guessing, and treat unavailable Git state as a typed non-zero error instead of an empty diff. Keep explicit symbols mutually exclusive with diff mode. Add tests for staged plus unstaged edits, multiple hunks, additions, deleted/unmappable files, non-Git roots, command failure, and paths containing spaces. Change nothing else.

- [ ] IMPACT-2: Adapt reverse impact traversal to the explanation contract
  Proceed only if impact is authorized. Refactor or wrap `getImpactRadius` so request-specific lower bounds, remaining node/time allowance, resolved seed reasons, direct dependants, and transitive depth groups are returned while preserving all-tier reverse CALLS/REFERENCES/IMPLEMENTS/INHERITS semantics. Order every frontier by the shared comparator without splitting HEURISTIC rows, preserve freshness and existing token-budget estimation/omission disclosure, and never use “will break” or “blast radius.” Add regression tests for cycles, multiple seeds, every edge kind, cross-tier order, exact-fit and each bound, diff-derived seeds, and unchanged existing MCP behavior. Change nothing else.

- [ ] EXPLAIN-4: Add one seed-scoped structural-test lookup for both projections
  Add a shared incoming TESTS reader invoked once after seed resolution: flow uses only its source seed, never `--to` or path nodes; impact uses its explicit or diff-derived seed set. Deduplicate test symbols/files, order retained edges with the total comparator, consume the request's remaining node allowance, never enter either primary traversal, and always label rows HEURISTIC with the coverage caveat. When no producer/evidence exists, render the identical unavailable-evidence sentence rather than infer tests from filenames or claim none exist. Test injected TESTS rows, duplicate seeds/files, remaining-cap truncation, flow-target exclusion, and the unavailable case. Change nothing else.

- [ ] EXPLAIN-5: Select exactly two evidence-backed next source files
  Add a pure selector implementing spec §6's candidate sequence: distinct non-test seed files by stable key; primary symbols by depth, tier, score, stable key, path; then flow-only fan-out and possible-link files in the same order. Keep the earliest qualifying position, exclude TESTS/unresolved/external/parse-failure/filename guesses, and include a targeted flow destination only when a displayed resolved path reached it. Test duplicate paths, multiple impact seeds, reached/unreached targets, auxiliary-only files, and the exact one-file and zero-file shortfall sentences. Change nothing else.

- [ ] EXPLAIN-6: Render deterministic projection-specific Markdown
  Add a pure Markdown renderer with the exact ownership marker and H1, fixed H2 order, fixed Request and Evidence-state field order, compact answer, flow `Static structural paths` or impact `Impact by depth`, Read next, flow-only auxiliary section, structural tests, and limits/warnings. Golden-test both projections, dirty/partial states, no path, all bounds, all next-file cardinalities, hostile Markdown/HTML strings, and byte identity on repeated renders. Change nothing else.

- [ ] EXPLAIN-7: Add atomic Sonde-owned repository file replacement
  Extend `RepoBoundary` with a focused generated-artifact writer used by explanations: validate repository-relative destination and links, re-check the real parent to defeat symlink-parent escapes, require the exact ownership marker before overwrite, render/validate fully before opening, create a known sibling temporary file, write and flush it, close it, atomically rename it, and remove only that known temp on failure while preserving the prior good artifact. - [ ] EXPLAIN-8: Wire the passing projection commands into the CLI
  Add a Commander `sonde explain` family only for projections authorized by FOCUS-7, using the exact spec §3 arguments and options. - [ ] EXPLAIN-10: Document and clean-install verify the supported explanation surface
